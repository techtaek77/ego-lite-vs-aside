04 / WHICH ONE?

그래서 내 상황엔 뭘 쓸까?

EGO LITE 먼저

볼트 + Codex + 웹 검증

기존 Codex 작업을 이어서 웹 앱 화면을 확인하고, 현재 탭의 포커스를 지키고 싶을 때. 기존 no-focus 운영 방식과 맞는지 시험해보기 좋아.

ASIDE 먼저

탐색부터 실행까지 한곳에서

브라우저에서 바로 질문하고, 자료 탐색·계정 작업·반복 루틴을 처리하고 싶을 때. Guard 및 승인 설정부터 살펴보자.

둘 다 시험

로그인된 웹 서비스 자동화

같은 테스트 계정과 같은 목표로 시작해서 완료율·실수·개입 횟수를 비교해. 기능 소개만으로 실사용 승자를 정할 수 없어.

나는 어떤 사람일까? 내 일부터 찾아보자

각자 자주 하는 일로 살펴보면 선택이 훨씬 쉬워져. 추천은 시작점이고, 실제로 쓰는 도구에 따라 달라질 수 있어.

일반 사용자 · ASIDE 먼저

여행을 준비하는 사람

이럴 때: 숙소와 교통편을 여러 사이트에서 찾아보고, 가격과 조건을 한눈에 비교하고 싶어.

💬 “부산역 근처 숙소 세 곳을 찾아서 가격과 체크인 시간을 정리해줘.”

왜 Aside? 브라우저에서 바로 AI에게 부탁할 수 있어 시작하기 쉬워. 예약이나 결제 전에는 내용을 직접 확인하자.

웹디자이너 · ASIDE 먼저

새 랜딩 페이지를 디자인하는 사람

이럴 때: 참고 사이트 여러 곳을 둘러보고, 첫 화면 구성과 색상 사용을 비교하고 싶어.

💬 “이 세 사이트의 첫 화면 구성과 공통 디자인 요소를 표로 정리해줘.”

왜 Aside? 브라우저에서 레퍼런스를 살펴보며 바로 질문하기 좋아. Codex로 만든 화면을 이어서 확인한다면 Ego Lite도 잘 맞아.

프로그래머 · EGO LITE 먼저

웹 앱을 만들고 확인하는 사람

이럴 때: Codex에게 만든 예약 화면이 저장 후 새로고침해도 유지되는지 확인시키고 싶어.

💬 “방금 수정한 예약 화면을 열어 저장하고, 새로고침 후에도 값이 유지되는지 확인해줘.”

왜 Ego Lite? 기존 코딩 에이전트의 작업 맥락을 이어서 브라우저 검증을 맡기기 좋아. Aside도 CLI와 MCP를 제공하니 직접 비교해볼 수 있어.

기획자 · ASIDE 먼저

서비스 흐름을 비교하는 사람

이럴 때: 경쟁 서비스의 가입 과정과 첫 화면을 살펴보고 개선 아이디어를 정리하고 싶어.

💬 “이 서비스 세 곳의 가입 단계를 비교하고, 사용자가 막힐 만한 지점을 정리해줘.”

왜 Aside? 브라우저에서 직접 탐색하고 질문하는 흐름에 어울려. 실제 가입이나 제출이 필요한 단계는 직접 판단하자.

마케터·콘텐츠 제작자 · ASIDE 먼저

자료를 모아 콘텐츠를 기획하는 사람

이럴 때: 여러 브랜드의 공개 캠페인을 조사하고 메시지와 형식의 차이를 정리하고 싶어.

💬 “이 브랜드들의 최근 공개 캠페인을 찾아 주제와 표현 방식을 비교해줘. 출처도 남겨줘.”

왜 Aside? 자료 탐색과 정리를 브라우저에서 바로 시작할 수 있어. 게시나 발송은 초안을 확인한 뒤 진행하자.

QA·테스터 · 상황에 따라

화면이 제대로 동작하는지 확인하는 사람

이럴 때: 테스트 계정으로 로그인해 버튼을 누르고, 결과와 오류 화면을 기록하고 싶어.

💬 “테스트 계정으로 목록을 열고 필터를 적용한 뒤, 결과가 맞는지 확인하고 오류가 있으면 기록해줘.”

어떻게 고를까? Codex 작업을 이어가면 Ego Lite, 브라우저에서 바로 탐색을 시작하면 Aside를 먼저 시험해봐. 반복 CI 테스트는 기존 Playwright와 각각 비교해야 해.

예시는 실행 결과가 아닌 요청 예시야. 사이트 권한, 모델, 요금제와 로그인 상태에 따라 결과가 달라질 수 있어.

“Obsidian과 Codex를 함께 쓰고, 작업 중 포커스를 지키는 게 중요하다면 Ego Lite부터 시험해보자. 브라우저 자체에서 조사와 반복 업무를 하고 싶어질 때 Aside를 나란히 비교하면 돼.”— 현재 작업 환경을 바탕으로 한 추천. 실제 설치·연동 및 성능은 아직 검증하지 않았어.
성능 숫자 주의: Aside가 공개한 벤치마크는 제작사 자체 발표이며 모델·설정·과제에 따라 달라져. Ego Lite와 같은 조건으로 직접 비교한 결과가 아니므로 이 글의 우열 근거로 쓰지 않았어. 발표와 조건 보기 ↗
05 / TRY IT YOURSELF

30분 공정 비교 실험

둘 다 설치하거나 계정을 연결하지 않았어. 아래는 직접 실행할 수 있는 검증 계획이야.

01 · 준비 두 도구의 버전, 모델, 권한, 동일한 테스트 계정을 기록해. 실제 결제나 발행이 없는 테스트 페이지를 고르고 현재 작업 창을 띄워둬.
02 · 단일 작업 로그인된 테스트 웹 앱에서 목록 확인 → 항목 변경 → 새로고침 → 변경 유지 확인. 각 도구에서 같은 지시문과 성공 조건을 사용해.
03 · 병렬·포커스 독립적인 읽기 작업 2개를 동시에 요청해. 포커스 이동, 로그인 재요청, 서로의 페이지 간섭과 실패를 기록해. Aside의 작업별 격리는 별도 확인.
04 · 결과 기록 성공/실패, 사람 개입 횟수, 실행 시간, 오류 재현 가능성, CPU·메모리와 모델 비용을 기록해. 3회 반복 후 같은 조건인지 함께 살펴봐.
테스트 페이지에서 지정한 항목의 상태를 변경하고 새로고침한 뒤
상태가 유지되는지 확인해줘. 현재 작업 창의 포커스를 빼앗지 말고,
결제·발행·삭제는 하지 마. 막히면 멈추고 이유를 알려줘.
결과에는 실행 단계, 성공 여부, 확인한 화면을 적어줘.

결함 주입, 녹화, Linear 연동은 영상 요약의 시연 내용이야. 두 제품 모두에서 기본 제공하거나 동일하게 동작한다고 확인된 기능은 아니므로 실험 전 별도 확인해.

06 / SECURITY & LIMITS

권한과 개인정보 체크

작은 권한으로 시작

테스트 계정과 읽기 중심 작업부터 시작하고 폴더 접근 범위를 좁혀. Aside의 새 작업 기본값은 Guard라고 문서에 나와 있어. Ego의 Codex 안내에 Full access 예시가 있지만, 필요성과 위험을 확인하고 무조건 켜지 말자.

로컬 실행도 데이터 경로 확인

로컬 브라우저라는 말이 모델에 데이터가 전송되지 않는다는 뜻은 아니야. 계정·모델 제공자·동기화 설정과 보존 정책을 확인해. 결제·게시·삭제는 확인 지점을 정해두자.

둘 중 어떤 게 더 빠르고 정확해?

현재 비교 실측이 없어 결론을 낼 수 없어. 같은 웹사이트, 같은 모델과 권한, 같은 성공 기준으로 반복해야 판단할 수 있어.

기존 Playwright를 완전히 바꿔도 돼?

아직 단정할 수 없어. 재현 가능한 CI 회귀 테스트, 브라우저 매트릭스, 네트워크 제어와 아티팩트 수집은 현재 파이프라인과 각각 비교해야 해.

컴퓨터가 꺼져 있어도 실행돼?

Ego의 로컬 Space는 켜진 컴퓨터에서 동작해. Aside의 원격·클라우드 기능은 플랜과 설정에 따라 달라질 수 있으니 실제 제공 여부를 별도 확인하자.
